# wow-mcp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local stdio MCP server, `wow-mcp`, giving Claude read-only tools for Jeremy's WoW Forever characters (Blizzard's undocumented `profile-forever` API) and WoW Forever game data (ForeverDB's API).

**Architecture:** One Go binary with subcommands (`serve`, `login`, `keys`, `probe`, `doctor`). Two API client packages (`blizzard`, `foreverdb`) behind one tools package that registers MCP tools with the official Go MCP SDK. Secrets in the login Keychain via `/usr/bin/security`; config in TOML. Two tracks: Tasks 1–6 need no Blizzard client; Task 7 is the step-0 gate; Task 8 builds on its findings.

**Tech Stack:** Go 1.26.4, `github.com/modelcontextprotocol/go-sdk` (latest v1), `github.com/BurntSushi/toml` v1.6.0, `net/http/httptest` for tests.

**Spec:** `docs/superpowers/specs/2026-11-19-wow-coach-design.md`

## Global Constraints

- Repo `~/projects/wow-app`, Go module `wowapp`, `go 1.26.4`. Not yet a git repo: Task 1 runs `git init` (branch `main`).
- Read-only against every API. No writes to Blizzard, ForeverDB or the game.
- Secrets only in the login Keychain, service `wow-app`, accounts `blizzard-client-id`, `blizzard-client-secret`, `foreverdb`, `blizzard-user-token`, `blizzard-user-token-expiry`. Never in config, argv, logs, tool results or errors (scrub every error of every key read).
- Config `~/.config/wow-app/config.toml`; a missing required value or unknown key is an error naming it.
- ForeverDB: base `https://foreverdb.net/api/v1`, key in `X-API-Key`; 429 → honour `Retry-After` once within the call's budget, then fail; 402 → fail with "ForeverDB quota used up for today". Every ForeverDB tool result carries `"source": "https://foreverdb.net"`.
- Blizzard: token `https://oauth.battle.net/token`, authorize `https://oauth.battle.net/authorize` (scope `wow.profile`), API `https://{region}.api.blizzard.com`, bearer header, `locale=en_US`. Regions `us`, `eu`, `tw` (KR is known to 403).
- `wow-mcp login` redirect URI: `http://localhost:47830/callback` (fixed; Jeremy registers exactly this).
- Expired/missing user token message, exact copy: `Your Battle.net login has expired; run wow-mcp login.`
- No placeholder or guessed character data, ever (spec anti-goal). If the character API can't answer, the tool returns an error saying so.
- Tests that hit real APIs skip under `testing.Short()`; everything else uses `httptest` with scrubbed recorded responses under `testdata/`.

## Review Focus

1. Character or realm names with capitals, spaces, apostrophes or non-ASCII (`Ælfwine`, `Argent Dawn`) → realm slugged (lowercase, spaces→`-`, apostrophes dropped), name lowercased and path-escaped; test in Task 8.
2. ForeverDB 429 on the second of several calls in one answer → one retry after `Retry-After`, then a clear tool error, never a hang past the call budget; test in Task 4.
3. User token expires between two tool calls → exact login copy, not a raw 401; test in Task 6.
4. A huge ForeverDB list (e.g. all items) → capped at 25 entries plus a `"truncated": true` flag so Claude's context isn't flooded; test in Task 5.
5. Keychain item missing for ForeverDB while Blizzard keys exist → game tools fail naming `wow-mcp keys set foreverdb`; character tools unaffected; test in Task 5.
